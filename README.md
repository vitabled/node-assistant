# node-assistant

Панель для развёртывания и обслуживания инфраструктуры Remnawave: ноды, панели,
хосты, мониторинг, автоматизация и биллинг — в одном self-hosted сервисе.

Стек поднимается одной командой за nginx-реверс-прокси с автоматическим
Let's Encrypt-сертификатом.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/vitabled/node-assistant/main/install.sh | sudo bash -s -- --domain panel.example.com --email you@example.com
```

Перед запуском направьте **A-запись** домена на этот сервер: сертификат
выдаётся через HTTP-01, а он проверяется по публичному порту 80.

Скрипт сам поставит Docker (если его нет), склонирует репозиторий в
`/opt/node-assistant`, сгенерирует секреты, соберёт и запустит стек, получит
сертификат и создаст шорткат `node-assistant`. После завершения откройте
`https://panel.example.com` и создайте аккаунт.

### Без домена (только HTTP)

```bash
curl -fsSL https://raw.githubusercontent.com/vitabled/node-assistant/main/install.sh | sudo bash -s -- --no-tls
```

Подойдёт для локальной сети или быстрой пробы. Для интернета не годится —
токены сессий пойдут в открытом виде. Домен можно добавить позже:
`sudo node-assistant set-domain panel.example.com`.

### Если хочется сначала посмотреть код

```bash
git clone https://github.com/vitabled/node-assistant.git /opt/node-assistant
cd /opt/node-assistant
sudo ./install.sh --domain panel.example.com --email you@example.com
```

### Отладка DNS и файрвола

Добавьте `--staging` — сертификат выпустится тестовым CA Let's Encrypt: браузер
будет ругаться, зато **лимитов нет** и ошибка в DNS ничего не стоит. Потом
запустите без `--staging`: установщик сам заметит тестовый сертификат и заменит
его настоящим.

## Управление

После установки скрипт доступен как `node-assistant` (симлинк в чекаут, поэтому
всегда запускается установленная версия):

```bash
sudo node-assistant status            # состояние стека, срок сертификата, версия
sudo node-assistant check-updates     # есть ли новая версия (exit 10 = есть)
sudo node-assistant update            # git pull → пересборка → перезапуск
sudo node-assistant set-domain new.example.com
sudo node-assistant set-ports --http-port 8080 --https-port 8443
sudo node-assistant reset-admin       # забыт пароль от панели
```

### Забыт пароль суперпользователя

Своей регистрации в панели нет, а сменить пароль в интерфейсе может только тот,
кто уже вошёл, — поэтому единственный путь назад лежит через хост:

```bash
sudo node-assistant reset-admin                      # спросит логин и новый пароль
sudo node-assistant reset-admin --login owner --generate   # сгенерирует и покажет один раз
```

Логин можно не указывать, если суперпользователь один. Пароль вводится вслепую с
подтверждением и **никогда не передаётся аргументом** — иначе он остался бы в
`/proc/<pid>/cmdline` и в истории оболочки. После сброса прежние сессии этого
пользователя перестают работать (API-токены живут своей жизнью — отзывайте их в
панели).

Это не обход модели прав: у кого есть shell на сервере, тот уже читает
`ENCRYPTION_KEY` из `.env`, а с ним может подписать сессию любому пользователю.
Команда лишь делает законный путь удобнее.

Автообновление по cron (`check-updates` возвращает 10, если апдейт есть):

```bash
0 6 * * * /usr/local/bin/node-assistant check-updates >/dev/null || \
          /usr/local/bin/node-assistant update -y
```

`update` не тронет чекаут с локальными правками — сначала попросит их убрать.

Обновляться можно и из самой панели: **Настройки → Обновления**.

## Возможности

**Ноды Remnawave**
- Деплой по SSH в 14 шагов: подготовка ОС, Node Accelerator, TrafficGuard,
  смена SSH-порта по dual-port-схеме с проверкой после перезагрузки, DNS + SSL,
  remnanode, маскировочный сайт, WARP, Hysteria2.
- Варианты ноды eGames / vanilla, режим HAProxy-реле, автодетект уже
  установленного сервера, переустановка и удаление отдельных компонентов.
- Автосоздание хостов в панели из локальных шаблонов, привязка к балансерам
  (selector в XRAY_JSON-шаблонах), смена домена ноды.

**Панель Remnawave**
- Установка панели (Caddy или nginx), страницы подписок с каталогом оформлений,
  редактор переменных `.env`, бэкап и восстановление, синхронизация панелей,
  миграция с Marzban, Prometheus-метрики.

**Мониторинг**
- Статус-страница доступности на базе xray-checker: аптайм за 30 дней, инциденты,
  группировка по подписке и стране, несколько инстансов чекера.
- Отдельная вкладка доступности серверов (TCP/ICMP-пробы), импорт серверов из
  подписки, скрытие узлов из отслеживания.
- Статистика пользователей и нод, тесты скорости «любой ↔ любой» (iperf3,
  Ookla, xray-туннель).

**Автоматизация**
- Движок правил: триггеры (падение узла, вебхук Remnawave, cron), условия,
  действия (Telegram, скрытие хостов, включение/отключение нод и юзеров).
- Встроенный ИИ-ассистент с read-only инструментами, MCP-сервер, промпт-пресеты.
- Автобэкап аккаунта в Telegram по расписанию.

**Инфраструктура**
- Каталог хостингов с картой, тарифами, тегами и ASN; анализ подписки
  (traceroute-гео, реестровое гео, ASN и его сайт).
- HAProxy через панель NodeFlow (разворачивается локально автоматически либо
  подключается существующая), Certwarden, Netbird, инфра-биллинг.
- Редакторы Xray-профилей, mihomo-конфигов и пользовательских конфигов,
  библиотека заметок и файлов, экспорт/импорт данных.

Всё изолировано по аккаунтам: у каждого свои настройки, шаблоны, правила и
статистика.

## Требования

- Linux-сервер с root-доступом (проверялось на Debian/Ubuntu; установщик умеет
  `apt`, `dnf`, `yum`).
- Docker — установщик поставит сам, если его нет.
- Свободные порты 80 и 443 (можно изменить, см. ниже).
- Для HTTPS: домен с A-записью на этот сервер и доступный из интернета порт 80.

## Порты

Установщик спросит порты веб-входа, по умолчанию 80 и 443 — достаточно нажать
Enter. Менять их потом: `sudo node-assistant set-ports`. Это единственные порты,
которые публикуются на хост; остальные сервисы общаются по внутренней
docker-сети.

> **Важно:** Let's Encrypt проверяет http-01 по **публичному порту 80**. Если
> перенести HTTP на другой порт, автоматическая выдача и продление сертификата
> работать не будут — установщик предупредит и пропустит выдачу. Нестандартный
> HTTPS-порт поддерживается полностью: редирект укажет его явно.

## Как это устроено

```
            :80 / :443
                │
        ┌───────▼────────┐   /.well-known/acme-challenge ──► certbot (продление)
        │ proxy (nginx)  │   /api/, /ws/ ──► backend (FastAPI)
        │ TLS + маршруты │   /            ──► frontend (React SPA)
        └────────────────┘   /internal/   ──► 404
```

- **backend** — FastAPI, данные в JSON/SQLite на томе `node-data`, аутентификация
  по JWT, изоляция по аккаунтам.
- **frontend** — React 18 + TypeScript + Vite + Tailwind.
- **proxy** — единственная публичная точка входа; конфиг выбирается в рантайме
  по наличию сертификата, поэтому первая выдача проходит без ручных шагов.
- **certbot** — продление каждые 12 часов; прокси сам перечитывает сертификат.
- Часть контейнеров (xray-checker, MCP, NodeFlow, CLIProxyAPI) backend запускает
  сам через docker-сокет, они не поднимаются вместе со стеком.

Подробнее: [docs/deploy.md](docs/deploy.md) — развёртывание и эксплуатация,
[CLAUDE.md](CLAUDE.md) — справочник по архитектуре.

## Безопасность

- `.env` содержит `ENCRYPTION_KEY` — им подписываются сессии и шифруются
  хранилища секретов. Файл создаётся с правами `600`; сделайте резервную копию и
  не коммитьте его. Установщик никогда не перегенерирует существующий ключ.
- **Первый созданный аккаунт наследует существующие данные** — создайте его до
  того, как дадите ссылку кому-то ещё.
- SSH-креды нод не хранятся на сервере: они передаются на каждый запрос.
- `/internal/*` наружу не выставляется (прокси отдаёт 404).

## Обновление и откат

```bash
sudo node-assistant update      # на текущей ветке
cd /opt/node-assistant && docker compose logs -f
```

Тома с данными (`node-installer_node-data`) и сертификатами
(`node-letsencrypt`) переживают `docker compose down`. Не удаляйте том с
сертификатами — иначе повторная выдача пойдёт в счёт лимитов Let's Encrypt.

## Лицензии вендоренных компонентов

В репозиторий вендорены сторонние проекты, у которых **в апстриме нет файла
лицензии**: `nodeflow/` (панель NodeFlow, см. [nodeflow/VENDORED.md](nodeflow/VENDORED.md))
и `frontend/public/mihomo/` (mihomo-configurator). Учитывайте это при публичном
распространении сборки — атрибуция авторам сохранена в коде. Форк MCP-сервера в
`mcp/` — MIT (заявлено в `mcp/package.json` и его README; отдельного файла
лицензии апстрим не приложил).

У самого node-assistant файла лицензии нет — права по умолчанию за автором
репозитория.
